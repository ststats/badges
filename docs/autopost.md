# 소주양 공지 → 와이고수 자동 등록

대상: `soju2022`가 쓴 SOOP 글 → `https://ygosu.com/board/pan_sojuyang`.
공개 글과 즐겨찾기 전용 글 모두 대상입니다. SOOP에 로그인해서 읽을 수 있는 계정의 쿠키를 사용합니다.
기존 뱃지와 일정은 그대로 작동합니다.

## 디자인

기존 뱃지와 같은 프로필/파스텔 머리/흰 카드에 **전체 제목, 전체 본문, 사진 전부**를 담습니다.
원문 HTML의 문단·사진 순서를 유지하고, 원문에 따로 첨부된 사진도 모두 넣습니다.
기존 뱃지의 10줄·3줄·사진 4장 제한이나 썸네일 자르기를 적용하지 않습니다.
긴 공지는 약 1800px마다 이어지는 PNG로 나눠 한 글에 순서대로 업로드하며 원문 링크를 붙입니다.
이미지 높이는 내용에 따라 달라집니다. GIF는 캡처 시점의 정지 화면입니다.
영상, 전체 본문 누락, 다운로드 실패, 지원하지 않는 이미지 호스트는 생략해서 올리지 않고 실행을 실패시킵니다.
원문 이미지는 SOOP/아프리카 도메인만 허용합니다.

## 설정

GitHub 저장소 **Settings → Secrets and variables → Actions**에서 설정합니다.
비밀번호와 쿠키는 코드·커밋·Variables에 넣지 않습니다.

| 종류 | 이름 | 값 |
|---|---|---|
| Secret | `YGOSU_ID` | 와고 일반 로그인 아이디 |
| Secret | `YGOSU_PASSWORD` | 와고 비밀번호 |
| Secret | `SOOP_COOKIE` | 즐겨찾기 글을 읽을 수 있는 SOOP 계정의 cookie 헤더 전체 |
| Variable | `AUTOPOST_ENABLED` | `true`이면 동작, `false`이면 중지 |

기존 상태 화면에 저장한 SOOP 쿠키를 재사용하려면 `SOOP_COOKIE` 대신
Vercel에서 쓰는 것과 같은 **Secret `COOKIE_KEY`**를 설정합니다. 둘 다 있으면 `SOOP_COOKIE`가 우선입니다.
와고는 매 실행마다 아이디/비밀번호로 로그인하므로 수동 로그인이나 와고 쿠키 복사가 필요하지 않습니다.
SOOP 쿠키는 만료될 수 있으며, 자동 갱신 기능은 없습니다.
쿠키를 바꿀 때는 설정한 출처(Secret 또는 기존 상태 화면)에서 갱신합니다.

1. 이 변경을 `main`에 병합합니다.
2. 위 Secrets를 저장하고 `AUTOPOST_ENABLED=true`로 설정합니다.
3. Actions → **소주양 공지 자동 등록** → **Run workflow**로 최초 실행합니다.
4. 최초 실행은 시작 시각을 기준으로 저장하고 과거 공지는 올리지 않습니다.
5. 이후 5분 간격 예약 실행에서 **최신 새 글 딱 1개만** 등록합니다. 밀린 글이 여러 개면 나머지는 건너뛴 것으로 기록해 이후에도 몰아서 올리지 않습니다.
6. 예약·수동 실행 모두 마지막 성공 등록 후 **5분 이내에는 추가 등록하지 않습니다**. GitHub의 예약 실행은 지연될 수 있습니다.

계정의 추가 인증/로그인 제한/글쓰기 권한/캡차가 있으면 해당 실행은 중단합니다.
Secrets 설정 전에는 실제 계정 로그인·등록 검증이 완료된 것이 아닙니다.
공개 목록과 로그인 목록을 비교해 최근 첫 페이지에 공개되지 않은 본인 글이 하나 이상 있어야 수집을 진행합니다.
최근에 즐겨찾기 글이 없으면 유효한 쿠키여도 검증할 수 없어 멈춥니다. 공개 글로 조용히 대체하지 않습니다.

## 중복 방지·오류 확인

전용 `autopost-state` 브랜치의 `state.json`에 시작 시각·SOOP 글 번호·와고 글 번호만 저장합니다.
이 브랜치는 코드 이력과 분리한 orphan 브랜치이며, 본문·사진·계정 정보는 저장하지 않습니다.
와고에는 캡처한 고정 이미지를 업로드하므로 원문이 수정되어도 이미 등록한 글은 바뀌지 않습니다.
게시 후 원문 수정·삭제를 와고에 자동 반영하지 않습니다.
동일 워크플로는 한 번에 하나만 실행하며, GitHub 상태 저장의 SHA 충돌 검사도 적용합니다.

등록 요청 **전에** `pending`을 저장합니다. 등록 응답이 불확실하거나 응답 뒤 기록 저장이 실패하면
다음 실행도 멈춰 중복 글 생성을 방지합니다. 준비 단계 오류는 다음 예약에서 다시 시도합니다.
실패 시 Actions 실행 결과와 마지막 단계 로그를 확인하세요. 요청 본문·인증 정보·스크린샷은 로그나 artifact로 남기지 않습니다.

`pending`이 남았을 때:

1. 먼저 `AUTOPOST_ENABLED=false`로 중지합니다.
2. 와고 게시판에서 해당 SOOP 공지가 실제로 올라갔는지 확인합니다.
3. 올라갔다면 `state.json`의 `done`에 `"SOOP번호": 와고글번호`를 추가하고 `pending`을 삭제합니다.
   확실히 등록되지 않았다면 `pending`만 삭제합니다. 상태 파일 자체를 지우면 새 기준으로 초기화되어 누락될 수 있습니다.
4. `AUTOPOST_ENABLED=true`로 재개합니다.

전용 상태 브랜치를 Vercel Preview 배포 대상으로 추가하지 마세요.
GitHub Actions가 꺼지거나 SOOP 접근 검증에 실패하는 동안은 게시할 수 없습니다.
페이지는 최대 100쪽까지 조회하며 이를 넘으면 누락한 채 진행하지 않고 멈춥니다.

## 검증

`npm test`: 수집/중복/전송 전 상태 저장/불확실한 응답 중단/전체 내용 보존 검증.
`npx playwright install chromium && node scripts/preview-autopost.mjs`: 합성 긴 공지의 전체 이미지 생성·분할 검증.
실계정 Secrets 없이는 와고 로그인·업로드·등록을 끝까지 검증할 수 없습니다.
